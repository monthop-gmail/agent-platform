# ADR-0037: ด่านที่อ่านคำประกาศ ครอบได้แค่คนที่ประกาศ — ทิศของการเดินสำคัญกว่าตัวกฎ

**Status:** **Accepted** (2026-10-17)
**Date:** 2026-10-17
**Depends on:** [ADR-0011](0011-conformance-automation.md) ขอบเขตของ `conformance/` · [ADR-0006](0006-contract-versioning.md) · [ADR-0034](0034-semantics-1-5-leaf-declaration.md) การเคาะ · [ADR-0036](0036-a-checksum-that-cannot-be-verified.md)
**Blocking:** `conformance/drift_check.py` → เช็ค `[5d] adrstatus` · ไม่แตะ contract ใด

## Context

[ADR-0034](0034-semantics-1-5-leaf-declaration.md) ค้างสถานะ `Proposed` อยู่ **27 วัน** หลังสัญญาที่มันบล็อกขึ้น production ไปแล้วทั้งคู่ · ไม่มีอะไรฟ้องเลยทั้งเดือน และคนที่เห็นคือคนที่เผอิญไปกวาดสถานะด้วยมือ

```text
event/v1    v1.8.0 · v1.8.1    ชิป 20–21 ก.ย.   อ้าง ADR-0034 ใน CHANGELOG
approval/v1 v1.3.0 · v1.3.1    ชิป 20 ก.ย.      อ้าง ADR-0034 ใน CHANGELOG
ADR-0034                       🕒 Proposed      20 ก.ย. – 17 ต.ค.
```

**ใบที่ยัง "เสนอ" อยู่ แต่ของที่มันเสนอขึ้น production ไปแล้ว คือบันทึกที่โกหกอยู่เงียบ ๆ** · `Grok` บันทึกรูปเดียวกันนี้ไว้ที่ `dis-9554f614` `seq 3` ว่าเกิดกับ decision บนโต๊ะ: *"ชี้แล้ว แต่ชี้ใบที่ยัง proposed — ผู้อ่านเห็น `dec-` id แล้วเชื่อเลย"*

การเคาะ ADR-0034 เสนอให้ปิดด้วยเครื่อง และ **เสนอทิศที่ผิด** — ให้ด่านอ่านบรรทัด `Blocking:` ของ ADR แล้วไปดูว่าเวอร์ชันนั้นชิปหรือยัง · ใบนี้มีอยู่เพราะทิศนั้นถูกวัดแล้วว่าตาบอด

## 🔴 วัดสองทิศก่อนเขียนโค้ด — ต่างกันสี่เท่าครึ่ง

### ทิศที่เสนอไว้ตอนแรก: อ่านจาก `Blocking:` ของ ADR

```text
ADR ที่ประกาศ Blocking เป็นเวอร์ชันชัด ๆ (`contracts/x/v1` → `v1.2.3`)     6 ใบ
ที่ประกาศหลวม — ชี้ไดเรกทอรี · ชี้ issue · "vocabulary gate" · "ไม่มี" · "—"   27 ใบ
                                                              ครอบคลุม  17%
```

**ด่านที่อ่านคำประกาศ ครอบได้แค่คนที่ประกาศ** — และ 27 ใบที่เขียนหลวมไม่ได้เขียนผิด พวกมันเขียนตามที่เรื่องของมันเป็น (ใบที่เขียนกฎ ไม่แตะสัญญา · ใบที่บล็อกทั้งไดเรกทอรี · ใบที่เป็น vocabulary gate)

เป็นความผิดตระกูลเดียวกับที่ [ADR-0036](0036-a-checksum-that-cannot-be-verified.md) เพิ่งรายงานวันนี้ว่า `architecture/consumers.md` นับ **การประกาศ pin** ไม่ได้นับ **การเอื้อมถึงผ่าน `$ref`** · และเป็น **false pass รูปที่หนึ่ง** ใน `conformance/README.md`: *ตัววัดไม่ได้อยู่ตรงจุดที่ของพัง*

> ถ้าเขียนด่านตามที่ ADR-0034 เสนอ เราจะได้ด่านที่เป็นแผลชนิดเดียวกับที่มันตั้งใจจะปิด — และมันจะพิมพ์ `ok` ให้ 83% ที่มันมองไม่เห็น

### ทิศที่เลือก: เดินจาก CHANGELOG ที่ชิปแล้ว → ADR ที่ entry นั้นอ้าง

```text
CHANGELOG entry ที่อ้าง ADR    79 รายการ
อ้างถึง                       27 ใบ จาก 35          ครอบคลุม  77%
```

ไม่ต้องให้ ADR ประกาศอะไรเพิ่มเลย เพราะ `([ADR-00xx](...))` ใน CHANGELOG **เป็นนิสัยที่รีโปนี้ทำอยู่แล้วทุกใบ** · ด่านจึงเกาะกับสิ่งที่คนทำจริง ไม่ใช่กับสิ่งที่เราอยากให้คนทำ

และสำคัญกว่าตัวเลข — **ทิศนี้เริ่มจากฝั่งที่มีความเสียหาย** คือสัญญาที่อยู่ใน production · ใบที่ยังไม่มีสัญญาไหนชิปตามมันไม่ได้สร้างความเข้าใจผิดกับใคร การที่ด่านมองไม่เห็นใบพวกนั้นจึงไม่ใช่ช่องเดียวกัน

### ทดสอบกับสภาพจริงของ `main` ไม่ใช่กับ fixture

```text
🔴 approval/v1  v1.3.1  อ้าง ADR-0034 ซึ่งเป็น Proposed
🔴 approval/v1  v1.3.0  อ้าง ADR-0034 ซึ่งเป็น Proposed
🔴 event/v1     v1.8.0  อ้าง ADR-0034 ซึ่งเป็น Proposed
                                            exit 1
```

**ด่านจับแผลที่มีอยู่จริงบน `main` วันนี้ได้ครบทั้งสามรายการ** ไม่ใช่จับ fixture ที่เราปลูกเอง — ข้อนี้เป็นหลักฐานที่แข็งที่สุดในใบ และเป็นเหตุที่ PR ของใบนี้ **แดงโดยเจตนา** จนกว่า ADR-0034 จะถูกเคาะเข้า `main`

## Options

### A. ไม่ทำด่าน — อาศัยคนกวาดเป็นรอบ
* ✅ ไม่มีโค้ดเพิ่มใน `conformance/`
* ❌ รอบที่ผ่านมาคนกวาดเจอหลัง 27 วัน และเจอเพราะเผอิญ ไม่ใช่เพราะมีรอบ
* ❌ รีโปนี้ปฏิเสธข้อนี้ไปแล้วหลายใบด้วยเหตุผลเดียว — *กฎที่อยู่ในหัวคนเดียวไม่ใช่กฎ*

### B. อ่านจาก `Blocking:` ของ ADR ตามที่ ADR-0034 เสนอ
* ✅ ตรงไปตรงมา และเป็นทิศที่คนคิดถึงก่อน
* ❌ **ครอบ 17%** · วัดแล้ว ไม่ได้เดา
* ❌ จะพิมพ์ `ok` ให้ 27 ใบที่มันมองไม่เห็น — สร้างความมั่นใจปลอม ซึ่ง `conformance/README.md` เขียนไว้เองว่าอันตรายกว่าไม่มี check

### C. เดินจาก CHANGELOG ที่ชิปแล้ว → ADR ที่มันอ้าง ⭐
* ✅ **ครอบ 77%** และเกาะนิสัยที่มีอยู่แล้ว ไม่ต้องขอให้ใครเปลี่ยนวิธีเขียน
* ✅ เริ่มจากฝั่งที่มีความเสียหายจริง
* ✅ จับแผลจริงบน `main` ได้ทันทีที่เขียนเสร็จ
* ❌ ไม่ใช่ 100% — 8 ใบไม่ถูกอ้างใน CHANGELOG ไหนเลย ด่านมองไม่เห็น
* ❌ ตรวจได้ว่า *ใบที่ถูกอ้างถูกตัดสินแล้วไหม* ตรวจไม่ได้ว่า *อ้างใบที่ถูกต้องไหม*

### D. บังคับให้ ADR ทุกใบประกาศ `Blocking` ในรูปเข้ม แล้วค่อยทำ B
* ✅ จะได้ 100% ของ ADR
* ❌ **เป็นการแก้คนให้เข้ากับเครื่องมือ** · 27 ใบที่เขียนหลวมไม่ได้เขียนผิด และบางใบไม่มีเวอร์ชันจะประกาศจริง ๆ
* ❌ ของที่ต้องกรอกให้ครบเพื่อให้ด่านทำงาน จะถูกกรอกให้ผ่าน — รูปเดียวกับที่ `it-operations-hub` รายงานว่า `FAILPATH:` ถูกใส่ไว้ให้ตัวตรวจอ่านโดยที่เทสต์ข้างในว่างเปล่า

### E. ทำทั้ง B และ C
* ✅ ครอบมากที่สุดในทางทฤษฎี
* ❌ B ไม่ได้เพิ่มเคสที่ C จับไม่ได้เลยจากข้อมูลวันนี้ — 6 ใบที่ประกาศเวอร์ชันชัด ถูก C ครอบอยู่แล้วทั้งหมด · **เพิ่มโค้ดที่ไม่เพิ่มการจับ คือเพิ่มของที่ต้องดูแลเปล่า ๆ** ซึ่ง ADR-0011 ห้ามไว้

## Decision

**C** — เช็ค `[5d] adrstatus` เดินจาก CHANGELOG entry ที่ชิปแล้ว ไปหา ADR ที่ entry นั้นอ้าง และบังคับว่าใบนั้นต้องถูกตัดสินแล้ว

**เหตุผล:** คำถามที่ตัดสินไม่ใช่ *"กฎควรว่าอย่างไร"* — กฎชัดตั้งแต่ต้นว่า *สัญญาที่ชิปแล้วต้องไม่อ้างใบที่ยังไม่ถูกตัดสิน* · คำถามคือ **เดินจากไหน** และคำตอบนั้นต่างกัน 17% กับ 77% ซึ่งวัดได้ก่อนเขียนโค้ด · ปฏิเสธ D เพราะการบังคับให้คนกรอกช่องเพื่อให้ด่านทำงาน จะได้ช่องที่ถูกกรอกให้ผ่าน

**Authority:** Monthop Champaruang — Platform Owner / Architecture Authority of `agent-platform`

### กฎที่ตีพิมพ์

1. **CHANGELOG entry ของเวอร์ชันที่ชิปแล้ว ต้องไม่อ้าง ADR ที่ยังไม่ถูกตัดสิน** — `Proposed` · `Rejected` · ไม่มีบรรทัด `Status` → `FAIL`
2. **`Accepted` และ `Superseded` นับว่าถูกตัดสินแล้ว** — `Superseded` คือตัดสินแล้วถูกแทน บันทึกไม่ได้โกหก · ถ้าไม่ยอมรับ `Superseded` ด่านจะฟ้องประวัติที่ถูกต้องย้อนหลังทุกครั้งที่มีใบถูกแทน
3. **อ้าง ADR ที่ไม่มีไฟล์อยู่ → `FAIL`** — ตัวชี้ที่ชี้ไปที่ไม่มีอะไร ไม่ใช่ตัวชี้
4. **ADR ที่ไม่มีบรรทัด `Status` ต้องไม่ผ่านเงียบ** — ไม่มีสถานะ ≠ สถานะว่าง ≠ ตัดสินแล้ว
5. **เนื้อก่อนหัวข้อเวอร์ชันแรกของ CHANGELOG ไม่ใช่ entry ที่ชิป** — หมายเหตุหัวไฟล์จึงไม่ถูกนับ
6. **ตัวเลขความครอบคลุมต้องถูกพิมพ์ทุกครั้ง ไม่ใช่เฉพาะตอนผิด** — และต้องพิมพ์พร้อมประโยคว่า *ใบที่ไม่ถูกอ้างที่ไหนเลย ด่านนี้มองไม่เห็น ไม่ได้แปลว่าไม่มีผล* · ฟิลด์ที่โผล่เฉพาะตอนผิดปกติจะถูกมองข้ามตอนที่มันโผล่
7. **ด่านนี้ตรวจว่าใบที่ถูกอ้างถูกตัดสินแล้วไหม ไม่ได้ตรวจว่าอ้างใบที่ถูกต้องไหม** — การอ้าง ADR ที่ `Accepted` แต่ไม่เกี่ยวกับ entry นั้น ผ่านด่านนี้ และ **เครื่องตรวจไม่ได้เพราะต้องอ่านความหมาย**

### negative test — 7 เคส ทำตามวิธีที่ `conformance/README.md` บังคับ (`cp` เก็บ ไม่ใช้ `git checkout` คืน)

| เคส | ผลที่ต้องได้ | จริง |
| --- | --- | --- |
| **สภาพจริงของ `main`** — ADR-0034 `Proposed` | `FAIL` 3 รายการ | ✅ `FAIL=3` · `exit 1` |
| เคาะ 0034 เป็น `Accepted` | ไม่ FAIL | ✅ `ok · 79 entry` · `exit 0` |
| `Status: Superseded` | **ไม่ FAIL** | ✅ พิสูจน์กฎข้อ 2 |
| `Status: Rejected` | `FAIL` | ✅ `ซึ่งเป็น \`Rejected\`` |
| ลบบรรทัด `Status` ทิ้ง | `FAIL` | ✅ `ซึ่งเป็น \`ไม่มีบรรทัด Status\`` |
| CHANGELOG อ้าง `ADR-9999` ที่ไม่มีใบ | `FAIL` | ✅ `ซึ่งเป็น \`ไม่พบใบ\`` |
| อ้าง `ADR-9999` ใน **หัวไฟล์** ก่อนเวอร์ชันแรก | **ต้องไม่ถูกนับ** | ✅ พิสูจน์กฎข้อ 5 |

เคสแรกคือเคสตัดสิน — **เป็นแผลที่มีอยู่จริงบน `main` ไม่ใช่ fixture ที่เราปลูก** · และเคสที่สามกับเคสสุดท้ายคือสองเคสที่กัน false positive ซึ่งเป็นด้านที่ `conformance/README.md` เตือนว่าทำให้คนเลิกอ่าน

## Consequences

* **PR ของใบนี้แดงโดยเจตนา** — ด่านจับ ADR-0034 บน `main` ได้ 3 รายการ และ `drift` เป็น required check ของรีโป · มันจะเขียวเองเมื่อ [#91](https://github.com/monthop-gmail/agent-platform/pull/91) (0034 → Accepted) ถูก merge · **ด่านที่ไม่ควร merge ตอนที่รีโปยังละเมิดมันอยู่ คือด่านที่ทำงานถูก**
* **ครอบ 77% ไม่ใช่ 100%** — 8 ใบไม่ถูกอ้างใน CHANGELOG ไหนเลย ส่วนใหญ่เป็นใบที่เขียนกฎโดยไม่แตะสัญญา · ตัวเลขนี้อยู่ในผลลัพธ์ของทุกรอบ ไม่ได้อยู่แค่ในเอกสารนี้
* **กฎข้อ 7 คือช่องที่เหลืออยู่และเครื่องปิดไม่ได้** — อ้างใบที่ `Accepted` แต่ไม่เกี่ยวกัน ผ่านด่าน · ปิดต้องอ่านความหมาย ซึ่งอยู่นอกสิ่งที่ ADR-0011 ยอมให้ `conformance/` ทำ
* **ด่านนี้ไม่เรียก host ใดเลย** — เดินไฟล์ใน `decisions/` และ `contracts/` ของรีโปเราล้วน · ไม่ขัด [ADR-0011](0011-conformance-automation.md) ที่ยอมให้แตะได้แค่ `raw.githubusercontent.com` และรันแบบ offline ได้ทั้งหมด
* **ไม่เพิ่มภาระให้ใครเขียนอะไรใหม่** — ไม่ขอให้ ADR ประกาศ `Blocking` ให้ครบ ไม่ขอให้ CHANGELOG เปลี่ยนรูป · ถ้าวันหน้ามีคนเขียน CHANGELOG โดยไม่อ้าง ADR ด่านจะมองไม่เห็น entry นั้น และนั่นสะท้อนในตัวเลขความครอบคลุมโดยอัตโนมัติ
* **หนี้ที่เปิดไว้จาก [ADR-0036](0036-a-checksum-that-cannot-be-verified.md) ยังไม่ถูกปิดด้วยใบนี้** — ทะเบียนยังนับการประกาศ pin ไม่ได้นับการเอื้อมถึงผ่าน `$ref` · เป็นแผลตระกูลเดียวกันกับที่ใบนี้ปิด แต่อยู่ในไฟล์คนละใบและควรมี ADR ของตัวเอง
